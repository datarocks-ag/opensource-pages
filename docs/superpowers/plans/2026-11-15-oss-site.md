# oss.datarocks.ch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the static site `oss.datarocks.ch`: landing page, Provisioners collection page, one page per project, and per-project docs pulled from the project repos at their latest release tag.

**Architecture:** Two stages. A Node sync script (`pnpm sync`) reads the project data files, asks the GitHub API for each repo's latest release, license, docs folder and `CHANGELOG.md` at that tag, rewrites the markdown, and writes generated files (`src/generated/releases.json`, `src/content/docs/<repo>/docs/**`). Then `astro build` renders the custom pages (Astro) and the docs (Starlight + `starlight-sidebar-topics`, one topic per project). Per-project failures in sync only produce warnings.

**Tech Stack:** Astro, Starlight, starlight-sidebar-topics, `@fontsource/{montserrat,nunito,jetbrains-mono}`, unified/remark (`unified`, `remark-parse`, `remark-stringify`, `remark-frontmatter`, `unist-util-visit`), `yaml`, vitest; pnpm; Node 24 (TypeScript scripts run with Node's built-in type stripping, no tsx).

**Spec:** `docs/superpowers/specs/2026-11-15-oss-site-design.md`. The visual reference is the canvas linked there.

## Global Constraints

- Hosted on GitHub Pages, custom domain `oss.datarocks.ch`. `public/CNAME` holds exactly `oss.datarocks.ch`.
- GitHub org `datarocks-ag`. Image name pattern: `ghcr.io/datarocks-ag/<repo>:<version without leading v>`.
- URLs: `/` landing · `/provisioners/` collection · `/<repo>/` project · `/<repo>/docs/…` docs.
- First wave, in this order: `keycloak-provisioner`, `postgres-provisioner`, `nats-provisioner`, `redpanda-provisioner`, `gcp-emulator-provisioner`, `seaweedfs-provisioner` (collection `provisioners`), then `go-egress-mitm-proxy` (standalone, `docsPath: doc`). `debug-docker` is excluded.
- Versions, license and docs come only from the GitHub API at the latest release tag. Never hard-code a version. Never show default-branch docs.
- Dependencies are limited to the Tech Stack list. **`yaml` is the only one not yet approved in the spec.** Get Sebastian's OK before Task 2; if he declines, use `.json` data files instead (same schema).
- Colours: accent `#1301E9`, navy `#0A017B`, deep navy `#020165`, bg `#F7F7FB`, border `#E3E4EF`, strong border `#C6C8DC`, body text `#3B3D55`, muted `#55576F`, surface tint `#EEEFF9`, code bg `#0D0C2E`, code text `#E8E9F7`, allowed `#047857`, blocked `#B42318`.
- Fonts: Montserrat 500/600/700 (headings), Nunito 400/600/700 (body), JetBrains Mono 400/500 (code, repo names, labels). Self-hosted via @fontsource, so no requests go to Google.
- Logo: `public/datarocks-logo.svg`, copied from `https://datarocks.ch/assets/images/datarocks-logo.svg`.
- Copy rules:
  - No invented facts, stats or star counts.
  - The facts strip only states things true for every listed project, and the project count is computed.
  - The company CTA links to `https://datarocks.ch`.
- Accessibility:
  - WCAG AA contrast.
  - Real `<a>` and `<button>` elements.
  - Decorative graphics are `aria-hidden`.
  - No horizontal page scroll at 375px; wide tables scroll inside their own box.
  - The tile hover rotation is disabled under `prefers-reduced-motion`.
- Git:
  - Work happens on `feature/site-v1`; never commit to `main` after the initial commit.
  - Commit messages are imperative and carry no attribution lines.

## Review Focus

1. **A release exists but its tag has no docs folder** (true today for keycloak, nats, redpanda, seaweedfs). The project page shows "Documentation on GitHub" linking to the README at that tag, with no Docs nav entry and no broken `/docs/` link. Pinned in Task 3 and Task 8.
2. **The GitHub API fails for one repo** (rate limit 403, 5xx, network error). Sync logs a warning, the other repos still sync, and the page renders without a version chip; snippets use `:latest`. Pinned in Task 3 and Task 8.
3. **Fetched docs link outside the docs folder** (`../README.md`, `../config.example.yaml`, images). These become GitHub URLs at the tag, never dead site links. Pinned in Task 4.
4. **A fetched markdown file has no frontmatter title** (most READMEs-turned-docs). The title comes from the first H1, which is then removed from the body, or from the file name otherwise. Starlight must not fail the build. Pinned in Task 4.
5. **A standalone project (the proxy)** must not be counted in a collection or show a "More provisioners" section, and its slug must not collide with a collection slug. Pinned in Task 2 and Task 8.

### Task 4: Markdown rewriting for fetched docs

**Files:**
- Create: `scripts/sync/rewrite.ts` (replaces the stub)
- Test: `tests/rewrite.test.ts`, `tests/fixtures/markdown/*.md`

**Interfaces:**
- Produces:

```ts
export interface RewriteContext { repo: string; tag: string; docsPath: string; filePath: string /* repo-relative */ }
export function rewriteMarkdown(source: string, ctx: RewriteContext): string;
```
- Rules:
  1. A link to a `.md` file inside `docsPath` becomes the site URL `/<repo>/docs/<path without .md, index → folder>/`, and the anchor is kept.
  2. Any other relative link becomes `https://github.com/datarocks-ag/<repo>/blob/<tag>/<resolved path>`.
  3. A relative image becomes `https://raw.githubusercontent.com/datarocks-ag/<repo>/<tag>/<resolved path>`.
  4. Badge images (an image whose URL contains `/actions/workflows/`, `badge`, or `.badges/`) and their wrapping links are removed.
  5. With no frontmatter `title`, the first H1 becomes the title and is removed from the body. With no H1, the title is the file name in title case, so `getting-started` becomes "Getting started".
  6. Absolute URLs are left untouched.
  7. The frontmatter gets `editUrl: https://github.com/datarocks-ag/<repo>/edit/main/<filePath>`. Starlight's own frontmatter field renders the "Edit this page on GitHub" link.
